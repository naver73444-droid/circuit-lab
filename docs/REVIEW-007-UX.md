## 1. 결론

현재 프로젝트에 필요한 것은 엔진 교체나 대형 프레임워크 도입보다 **수치 모델과 표시의 분리, 입력·실행 상태의 일관성, 계측기형 그래프 조작, 정보 구조의 단순화**다. Godot용 Skill 자체가 아니라 “서로 다른 책임을 섞지 않게 만드는 규칙과 검사”라는 접근을 적용했다.

이번 제공본에는 실제 코드 변경, 독립 수치 회귀시험, 브라우저 조작 시험, 프로젝트 전용 Skill, 세 세션별 인계 문서를 포함했다. 구현된 것과 후속 과제를 아래에서 구분한다. 모든 잠재 결함이 없어졌다는 뜻은 아니다.

## 3. 부품 주변 × 문제: 의미와 조작을 분리

### 원본에서 확인한 사실
`src/circuit-status.js`의 `unwired` 메타데이터는 ×를 “미배선 핀”으로 정의한다. `styles.css`의 `.connection-badge`는 `pointer-events: none`이므로 눌러도 동작하지 않는다. 즉 원래부터 삭제 버튼이 아니었으나, 사용자에게 삭제 버튼처럼 보이는 설계였다.

### 구현한 변경
경고는 `!`로 바꿨다. 경고를 클릭하거나 키보드로 활성화하면 속성 패널의 연결 설명을 보여준다. 정상 연결에서는 불필요한 테두리/뱃지를 계속 표시하지 않는다. 선택한 부품에는 **별도의 실제 × 삭제 버튼**이 나타난다. Ctrl+Z로 복원된다.

실제 pointer capture를 쓰는 일반 클릭에서는 선택 상태만 바뀌고 삭제 버튼이 렌더링되지 않는 경우도 발견했다. pointer 종료 단계에서 선택 표시를 확정하도록 수정하고 브라우저 시험으로 재확인했다. 이것은 합성 click만 호출했으면 놓칠 수 있는 통합 문제였다.

삭제 시에는 부품 자체뿐 아니라 함께 삭제되는 배선에 연결된 프로브도 정리한다. 이전에는 살아 있는 다른 부품의 핀을 참조하는 프로브에 이미 삭제된 wireId가 남아 저장 파일을 다시 열지 못할 수 있었다.

## 4. 그래프: 숫자 입력 중심에서 눈금 조절 중심으로

### 구현한 기본 동작

| 조작 | 결과 |
|---|---|
| 프로브를 추가하거나 첫 결과를 받음 | 표시 범위 자동 맞춤 |
| 그래프 안에서 휠 | 시간 또는 로그 주파수 X축 눈금 |
| 왼쪽 눈금 위에서 휠 / Shift+휠 | 첫 번째 물리량 Y축 눈금 |
| 오른쪽 눈금 위에서 휠 / Alt+휠 | 두 번째 물리량 Y축 눈금 |
| 상단 시간·전압·전류 컨트롤 위 휠 | 해당 축 한 칸 값 조절 |
| 각 컨트롤의 − / + | 휠 없이 같은 단계 조절 |
| 그래프 드래그 | X축 표시 구간 이동 |
| 자동 맞춤 버튼 | 고정 배율을 해제하고 전체 결과에 다시 맞춤 |

눈금은 **1–2–5 계열**, 격자는 **가로 10칸·세로 8칸**이다. 예를 들어 100µs/div → 200µs/div → 500µs/div → 1ms/div처럼 움직인다. 직접 조절하면 “고정”, 자동이면 “자동”을 표시한다. 같은 해석을 다시 실행해도 사용자가 고정한 배율을 유지한다.

전압과 전류는 독립 축이고, 같은 물리량의 여러 trace는 공통 축이다. 각 축은 0 눈금까지 같은 SI 접두어를 사용한다. 작은 전류 trace를 임의로 개별 정규화해서 큰 전류와 같은 크기로 보이게 만들지는 않는다. 서로 크게 다른 같은 단위 신호를 비교해야 할 경우 채널별 오프셋/분리 보기 등은 후속 설계 과제다.

**표시 배율을 바꿔도 회로·소자값·초기조건·dt·원시 표본은 변하지 않는다.** CSV는 기존 SI 원시값을 유지한다. 이 변경은 오실로스코프의 화면 조작 방식을 참고한 것이며 실제 ADC, 트리거, 획득 엔진을 추가한 것은 아니다.

### 좌표와 성능 수정
원본 그래프는 표시 영역의 여백과 SVG 변환을 고려하지 않고 전체 DOM 폭을 표본 번호에 비례시켰다. 기준 RC 시험에서 그래프 시작 위치가 0s가 아니라 370µs를 읽었다. 수정본은 실제 SVG 화면 변환과 plot 영역을 사용하고, 실제 X 좌표 배열에서 가장 가까운 표본을 검색한다. 같은 시작 위치 시험에서 index0/0s를 확인했다.

커서 이동은 커서와 읽기값만 갱신하고 전체 파형/축을 다시 만들지 않는다. 브라우저 시험의 연속 여섯 번 이동에서 trace renderCount가 늘지 않았다. 이것은 그 시험 조건의 결과이며 전체 FPS 향상률이나 토큰 절약률을 측정한 것은 아니다.

표시용 데이터가 많으면 픽셀 구간별 처음/끝/최소/최대를 남기는 방식으로 SVG 경로를 줄인다. 좁은 peak를 단순 일정 간격 추출보다 덜 놓치도록 설계했으며, 원본 결과 및 CSV는 축소하지 않는다. 비유한 표본은 연결선으로 이어 그리지 않는다.

## 5. 해석과 학습 선택 간소화

기본 선택을 “관찰 목적” 하나로 묶었다.

| 선택 | 동작 |
|---|---|
| 자동 판단 | 시간 변화 소스 또는 C/L 유무로 DC/시간응답을 추천 |
| 회로 상태 | DC 동작점 |
| 시간 변화 | transient 시작 범위 제안 |
| 주파수 응답 | AC sweep 및 지정 페이저 |
| 직접 설정 | 기존 해석 종류와 수치 입력 보존 |

상세 시간·주파수 입력은 “고급 설정”에 남겼다. 직접 수치를 변경하면 직접 설정 모드로 넘어가 자동 추천이 덮어쓰지 않게 한다. 예제와 불러온 프로젝트는 기존 설정을 보존하고, 연결이 완성된 경우 자동 갱신으로 실행된다. 따라서 예제를 골랐다는 이유로 사용자가 run을 다시 눌러야 하지는 않는다. AC 페이저/임피던스 학습은 결과 아래 선택적 상세 보기로 옮겼다.

자동 실행은 입력 확정 후 250ms 지연하고, 새 회로·불러오기·undo·자동 갱신 해제 시 이전 예약을 취소한다. 실행 시 회로와 설정의 사본을 만들고 generation/실행 일련번호가 여전히 현재인지 검사한다. 이전 작업이 새 회로의 성공/실패/계산 중 표시를 덮어쓰지 않도록 했다.

### 자동화의 한계
현재 추천은 소자값과 소스 주기를 활용한 **시작 범위 휴리스틱**이다. 실제 회로 연결에서 정확한 극점과 모든 시간척도를 구한 것은 아니다. RC 첫 계단응답처럼 수동 설정 부담을 줄이는 데 목적이 있다. 긴 PULSE 주기가 RC 시정수보다 훨씬 긴 경우 첫 계단응답 중심으로 범위를 제안한다.

소스의 SIN/AC 정의, 초기 전압·전류, 배선은 자동으로 바꾸지 않는다. 충돌하는 IC가 있으면 오류를 보여준다. 빠른 현상과 느린 현상이 공존하거나 공진이 강한 복잡한 회로는 전문가 범위 설정 및 dt 수렴 확인이 필요하다. 자동화가 모든 물리적 판단을 대신한다고 안내하면 안 된다.

## 6. UI 시각 정리

기존의 여러 그라데이션, 발광, 큰 그림자, 과도한 둥근 카드, hover 이동을 줄였다. 밝은 중성 바탕과 얇은 경계선을 쓰는 실험 도구 방향으로 바꿨다. 색은 선택, 파형 구분, 오류에 집중시켰다. 외부 폰트나 UI 프레임워크는 추가하지 않았다.

1024px 화면에서 원본 결과 패널 오른쪽이 130px 벗어나던 문제는 1100px 이하에서 회로/결과 전환을 쓰는 방식으로 해결했다. 1440×900, 1024×768, 390×844에서 결과 패널과 문서 가로 폭이 viewport를 넘지 않는 것을 확인했다. 이 숫자는 시험 viewport 기준이며 모든 기기·배율의 보장은 아니다.

디자인 방향은 사용자의 “AI가 만든 느낌을 줄여 달라”는 요청에 대한 구현 제안이다. 밝은 테마가 정답이라는 객관적 판정은 아니며, 차후 어두운 실험실 테마가 필요하면 같은 정보 구조와 대비 기준을 유지한 색상 토큰으로 추가하는 편이 좋다.

## 8. 병렬 커패시터 초기조건: 수치 수정은 별도 승인 권장

이 문제는 앞선 검토에서 중요하게 지적됐으며 007에도 남아 있었다. 중복 제약 한 개만 제외해야 하는데 경로 안의 모든 커패시터 초기제약을 제외해, 병렬 C 두 개를 5V로 지정해도 초기 표본이 0V가 됐다.

단순히 전압 방정식 하나만 남기면 전압은 맞아도 남은 가지에 초기 전류가 전부 몰릴 수 있다. 따라서 호환되는 C/V 제약의 독립 집합을 선택한 후 초기 C·dV/dt와 알려진 R/D/I/L 전류가 KCL을 만족하도록 초기 전류를 재구성했다.

독립 기대값 예:

```text
C1 = 1 µF, C2 = 3 µF, R = 1 kΩ
C1과 C2는 병렬, 각 IC = 5 V

I_R(0) = 5/1000 = 5 mA
(C1 + C2) dV/dt + V/R = 0
I_C1(0) = -1.25 mA
I_C2(0) = -3.75 mA
```

원본 실행값은 V=0, 세 전류 모두 0이었다. 수정본은 V=5V, -1.25mA/-3.75mA/+5mA를 재현했다. 부품 순서 변경, C 삼각망, SIN 전압원과 일치하는 C 초기값 및 C·dV/dt, 서로 다른 IC의 명시적 오류를 추가 시험했다. 세부 수치는 `evidence/numeric-before-after.json`과 `tests/review-regression.test.mjs`에 있다.

**제한:** 중복 C 초기제약을 처리해야 하는 회로에 OP AMP가 포함되면 초기 미분계는 지원하지 않아 명시적으로 중단한다. 일부 회로는 기존 초기 solve에서 먼저 다른 제약 오류가 날 수 있다. 이것을 임의의 0A로 표시하지 않는다. 범용 DAE 초기화 해결책을 완성했다는 주장은 하지 않는다. 수치 변경은 설계·해석 세션의 검토 후 통합하는 것이 좋다.

| 변경 | 이유 |
|---|---|
| UnionFind를 `union-find.js`로 통합 | 엔진·연결 검사에서 자료구조 구현 중복 제거 |
| `scope-model.js` / `scope-view.js` 분리 | 표시 수학을 DOM 없이 시험하고, 화면 배율이 solver에 침투하지 않게 함 |
| `analysis-policy.js` 분리 | 자동 추천을 수치 해석 엔진과 구별 |
| `safe-dom.js` 도입 | 텍스트 escape와 안전한 color token 정책 공유 |
| `refreshProbeViews()` 통합 | 프로브 추가·삭제 경로의 동일 갱신 호출 반복 축소 |
| 연결 상태/표시 series cache | 같은 generation의 중복 계산과 커서 이동의 불필요한 전체 작업 축소 |
| CSS 재정리 | 연속 덮어쓰기 규칙을 다시 쌓지 않고 실험 도구용 기준으로 정리 |

단순 줄 수 감소가 목적은 아니다. 기준 `app.js` 1707줄은 이 후보에서 약 1757줄이며 새 기능과 입력 안전성 추가로 아직 큰 조정자다. 반면 CSS는 374줄에서 298줄로 정리했다. 수치 정확도 보강과 독립 시험 추가로 전체 코드량은 늘었다. 핵심은 책임이 분리돼 다음 변경을 더 작은 단위로 검증할 수 있다는 점이다.

후속 작업에서는 app에서 입력 draft/실행 coordinator를 순차 분리한다. 모든 if문을 없애기 위해 복잡한 추상화를 도입하거나, 실수/복소수 stamp를 검증 없이 하나로 합치지 않는다.

## 10. GitHub 조사와 적용 방법

우선순위는 **전용 경계 Skill → 브라우저 회귀시험 → UI 검토 Skill → 정적 검사 확장**이다.

- [Impeccable](https://github.com/pbakaus/impeccable): UI의 audit/quieter/distill/harden 등에 적합. 이 앱에서는 시각 효과 확대보다 실험 조작성과 정보 정리에 한정하는 것을 제안한다.
- [Playwright CLI](https://github.com/microsoft/playwright-cli): 실제 브라우저 동작 확인·스크린샷·에이전트 Skill. 이번에는 CLI가 아니라 Python Playwright로 시험했다.
- [jscpd](https://github.com/kucherenko/jscpd): 중복 탐지 후보. [Knip](https://github.com/webpro-nl/knip): 미사용 항목 탐지 후보. 둘 다 결과를 보고 자동 삭제하는 방식은 피한다.
- [dependency-cruiser](https://github.com/sverweij/dependency-cruiser): 엔진↔UI 경계와 순환 참조 규칙 검사에 적합. 현재 규모에서는 우선 번들의 경량 검사기를 사용했다.

자료에서 확인한 기능, 프로젝트 적용 제안, 실제 설치/실행 여부, 사용 예시는 `docs/github-tools.md`에 상세히 구분했다. 외부 도구들은 이 작업에서 설치·실행하지 않았으며 도구별 중복률/절약률/벤치마크를 주장하지 않는다.

직접 작성한 `.agents/skills/circuit-lab-boundary/SKILL.md`는 [OpenAI 공식 문서](https://developers.openai.com/codex/skills)의 폴더/메타데이터 형식을 따랐다. 프로젝트 폴더에 포함했지만 사용자의 Codex에서 실제 발견·활성화됐는지는 이 채팅에서 검증하지 않았다. `AGENTS.md`와 함께 다음 세션의 작업 기준으로 사용할 수 있다.

## 11. 검증 결과와 해석

| 검증 | 결과 | 범위 |
|---|---|---|
| 원본 Node 시험 | 70/70 통과 | 007의 기존 시험 |
| 개선본 Node 시험 | 100/100 통과 | 기존 70 + 회귀 24 + exporter 6 |
| 브라우저 회귀 | 22/22 통과 | Chromium 144, 오프라인 import-map 하네스 |
| 구조 경계 검사 | 오류 0, 경고 1 | 상대 import·순환·DOM 경계 패턴. app 크기 경고 유지 |
| HTTP smoke | 6/6 기대 상태 일치 | 실제 Node HTTP 서버에 Python 요청. 브라우저 HTTP와 구별 |
| 소스 export/restore | ZIP/TXT 동일 payload 및 복원 확인 | 최종 manifest와 검토 번들의 로그 참조 |

브라우저 시험은 예제 한 번 클릭, ! 설명, 실제 × 삭제/undo, 잘못된 숫자 입력, native 더블클릭, 새 회로 예약 취소, 자동 갱신 off, 해석 전환의 물리값 보존, RC 자동 범위, 커서 시작 좌표, X/Y 휠, 고정 배율 유지, 커서-only 갱신, 세 화면 크기, 삭제 후 저장/불러오기, 무해한 import 표식, pointer 소유권 해제, SI CSV를 포함한다.

### 반드시 읽을 검증 한계
검토 환경은 Linux/Node 22.16.0/Chromium 144.0.7559.96이다. 브라우저의 localhost 탐색이 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단돼, HTML/CSS와 ES module 전송만 인라인으로 바꾼 하네스에서 앱 로직을 실행했다. 정책을 해제하거나 우회 설정을 변경하지 않았다. 별도 HTTP smoke는 서버가 파일을 제공하는지만 확인했다.

따라서 Windows CMD 시작, 실제 Windows 브라우저 localhost 통합, 서버의 CSP 전달, Edge/Firefox/WebKit, 실기기 터치·휠/트랙패드 다양성, 125/150% 배율, 스크린리더, 장시간 큰 회로 실행은 검증 완료가 아니다. 이 후보를 바로 최종 릴리스라고 간주하지 않는다.

| 우선순위 | 과제 | 다음 판정 기준 |

## 13. 세 세션 운영

운영관리 세션은 범위·우선순위·통합·릴리스 승인을 맡는다. 설계·해석 세션은 독립 기대값과 허용오차를 정한다. 실행 세션은 코드 변경·시험·로그를 제출한다. 세션별 구체적인 첫 작업은 아래 파일에 있다.

```text
docs/session-1-management.md
docs/session-2-design-analysis.md
docs/session-3-execution.md
```

이번 후보를 받으면 먼저 원본을 별도 보존하고, UI/입력 안정화와 수치 초기조건 변경을 분리해서 검토한다. 서로 다른 세션이 같은 파일을 동시에 수정하지 않도록 담당 파일과 인계 시점을 정한다. 통합 후에는 한 기준 버전에서 전체 회귀시험을 다시 실행한다.
